# 如何在任务清单里给单条任务写清楚补充要求

> [!info] 写给任务条目越写越长、最后连自己都读不懂的你
> 一条 `- [ ]` 只能写一行，但任务里的约束往往不止一句：要覆盖哪些主题、沿用什么口径、避开什么雷区……全塞进一行，条目又长又乱，AI 也读得费劲。
> 读完这篇，你就知道怎么把补充要求写在「任务下面」，既清爽又能被 AI 读到。

---

## 一句话先记住

> [!tip] 核心结论
> 在 `- [ ]` **正下方缩进**写多行，会被当作「任务补充描述」一起注入这条任务的提示词。
> 但记住：**写在缩进行的控制标记（`@[[…]]` / `#ioto/…` / `[model:: …]`）不会生效**，那里只能放纯文字要求。
> 缩进可以使用缩进列表的形式，也可以使用`Shift+Enter`创建列表内的换行

---

## 怎么写补充要求

主行只写「要做什么」，把细节放到下面缩进：

```markdown
- [ ] 把三篇合并成一篇综述，放入 @[[综述]]
    只覆盖 A 与 B 两个主题，不要展开 C
    口径沿用 [[背景资料]] 里的说法，不要自创术语
```

这两行缩进文字会原样进入这条任务的 prompt，AI 执行时能看到。

> [!note] 缩进是「续行」不是「新任务」
> 缩进必须比 `- [ ]` 多至少两个空格。和 `- [ ]` 同列的，会被当成下一条任务，而不是补充描述。

---

## 补充描述写到哪算结束

从 `- [ ]` 下方的缩进行开始，遇到以下任何一种就**结束**，后面的内容不再属于这条任务：

| 终止条件 | 例子 |
| --- | --- |
| 空行 | 中间隔一个空行 |
| 标题 | `# 小节` |
| 分隔线 | `---` |
| 下一个 `- [ ]` | 新的一条任务 |
| 缩进回退 | 文字退回到和 `- [ ]` 同列 |

```markdown
- [ ] 写周报，放入 @[[周报]]
    先列本周完成的三件事
    再写下周计划
                 ← 空行：补充描述到此结束
- [ ] 顺便把周报发给团队
```

---

## 彩蛋：AI 回填的链接不会污染下一轮

如果你让 AI 把产出的笔记链接回填到任务下面，它通常会写成这样一行：

```markdown
- [ ] 写周报，放入 @[[周报]]
    - [[周报]]
```

**整行只有 `- [[链接]]` 的这一行，会被插件自动识别为「回填产物」并过滤掉**——下一轮执行时，它不会被当成任务描述，你也不用手动清理。

> [!tip] 为什么这点很实用
> 这意味着「让 AI 回填产物」可以放心用：回填的链接既留下了可追溯的记录，又不会在第二轮把 prompt 搞乱。

---

## ⚠️ 反例：控制标记不能写在这里

补充描述块**只认纯文字要求，不认控制标记**。想让 `@` / `#ioto/` / `[model:: ]` 这些生效，必须回到 `- [ ]` 同一行：

```markdown
✅ - [ ] 汇总本周进展，放入 @[[周报]] #ioto/fanout/3
❌ - [ ] 汇总本周进展，放入 [[周报]]
        #ioto/fanout/3          ← 只是补充描述，fan-out 不生效
        @[[周报]]               ← 也不算交付物
```

> [!warning] 最易踩的坑
> 写在缩进行的标记只是普通文字，会被一起塞进提示词，但**功能完全不生效**。解析器只读 `- [ ]` 那一行来识别控制项。
