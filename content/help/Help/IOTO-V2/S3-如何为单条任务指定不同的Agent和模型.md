# 如何为单条任务指定不同的 Agent 和模型

> [!info] 写给已经在用「AI 执行任务」、想让不同任务用不同 AI 的你
> 在 IOTO 的子任务编排模式下，你可以在**单条任务**里指定「这条用哪个 Agent、哪款模型」，而不必整个批次都用同一个。这样就能「粗活给便宜模型、细活给强模型」，把成本花在刀刃上。
> 读完这篇，你就知道三种写法分别怎么用、为什么其中一种是推荐写法。

---

## 一句话先记住

> [!tip] 核心结论
> 给单条任务换 Agent / 模型，**全部写在 `- [ ]` 同一行**，靠三种标记之一：
> - `#ioto/agent/<id>` —— 换 Agent
> - `#ioto/model/<id>` —— 换模型（但模型 ID 含 `.` 会被截断）
> - `[model:: <id>]` —— 换模型的**推荐写法**，支持任意字符
>
> 这条能力**纯靠条目声明 opt-in，没有任何设置项要开**，可以放心试。

---

## 为什么需要条目级路由

默认情况下，一个批次的所有任务用你在状态栏选好的那个 Agent / 模型。但真实场景里，任务的「贵贱」是不一样的：

- 有些只是**粗筛、分类、摘要**，不需要强模型；
- 有些是**成稿、写代码、做判断**，值得上强模型。

如果整批只能用同一个模型，要么全用贵的（烧钱），要么全用便宜的（质量不稳）。条目级路由让你**在同一批里混着来**。

> [!note] 这属于「Agent 能力下放」
> 路由不再只能全局切换（见 [[S3-在IOTO中如何配置和使用多个不同的Agent]] / [[S3-在IOTO中如何为Agent配置多个不同的模型]]），现在能精确到单条 checklist item，单任务与编排模式都生效，Dry Run 里也会同步显示「Agent / 模型」行。

---

## 三种写法

| 写法 | 作用 | 什么时候用 |
| --- | --- | --- |
| `#ioto/agent/<id>` | 本条改用指定 Agent | 这条任务想换一个 Agent 跑 |
| `#ioto/model/<id>` | 本条改用指定模型 | 模型 ID **不含 `.`**（如 `sonnet`） |
| `[model:: <id>]` | 模型覆盖的**推荐写法** | 模型 ID **含 `.`**（如 `gpt-4.1`、`claude-opus-4-5`） |

```markdown
- [ ] 调研一下竞品定价，用便宜模型即可 #ioto/agent/claude #ioto/model/haiku
- [ ] 把调研结果写成一篇正式综述，放入 @[[竞品综述]] [model:: claude-opus-4-5]
```

Agent 的 `<id>` 大小写不敏感；非法值只会告警并回退全局（见下文「写错了会怎样」）。

---

## 为什么推荐 `[model:: <id>]`

模型 ID 常常带点号，比如 `gpt-4.1`、`claude-opus-4-5`、`gemini-2.5-pro`。而 Obsidian 标签**只认字母、数字、`_`、`-`**——碰到 `.` 就把标签截断。

```markdown
❌ - [ ] 润色这封信 #ioto/model/gpt-4.1     ← 标签在 "." 处被截断成 gpt-4
✅ - [ ] 润色这封信 [model:: gpt-4.1]        ← 完整保留 gpt-4.1
```

`[model:: …]` 是内联字段，支持**任意字符**（含 `.`、空格），而且**优先级高于** `#ioto/model/`。所以只要模型 ID 不是纯字母数字连字符，一律用 `[model:: …]` 最保险。

> [!warning] 标签能用的字符有限
> 空格、`.`、`:`、`[`、`]`、`,` 都会把标签截断。记住一句口诀：**模型 ID 里有点的，用 `[model:: …]`；没有点的，两种都行。**

## 典型配方表

| 任务类型 | 推荐模型档位 | 理由 |
| --- | --- | --- |
| 调研 / 粗筛 / 分类 / 抽取 | 便宜档（如 `haiku`、`mini`） | 量大、容错高，不值得上强模型 |
| 摘要 / 翻译 / 格式整理 | 中档 | 稳定即可 |
| 成稿 / 写代码 / 做判断 / 复杂推理 | 强档（如 `opus`、`4.5`） | 质量敏感，值得投入 |

```markdown
- [ ] 把 20 篇评论按正/负/中分类 #ioto/model/haiku
- [ ] 基于分类结果写一份情绪分析，放入 @[[情绪报告]] [model:: claude-opus-4-5]
```

## 写错了会怎样

放心试。**非法 Agent 不会让你整批崩掉**：

- 写了不存在的 `#ioto/agent/<id>`：控制台只告警，并**回退到全局 Agent**，**不阻断**执行；
- 模型 ID 无法静态校验（不知道你电脑上到底有没有这个模型），所以只做「拒绝含换行 / NUL」的最小注入校验后透传，最终效果由底层 CLI 决定。

换句话说：**路由是「锦上添花」，不是「前置门槛」**。写错了最多就是「没换成」，不会搞坏任务。

> [!tip] 用 Dry Run 验证路由成功
> 不确定标记有没有被识别？跑一次「预演 AI 任务（Dry Run）」，看每条渲染出来的 `Agent` / `模型` 行对不对（见 [[S3-如何在真正执行前先预演一遍AI任务]]）。
