# 模板与状态文件

## 卡片笔记模板

路径：`2-输出/卡片笔记/{标题含是什么/为什么/如何}.md`

```markdown
---
Project: ["项目名"]
---

# {标题：围绕一个主题，含「是什么 / 为什么 / 如何」等关键词}

{提炼后的卡片内容：围绕一个主题组织，自包含。
用清晰结构（定义 → 要点 → 示例）重写，不是简单摘抄闪念原文。}

{可选：要点列表、对比表、代码块、示例}

## 来源

- [[闪念-2024-01-01]]
- [[闪念-2024-01-02]]
```

> 回链用源闪念的**真实文件名**（去掉 `.md`）。文件名 = `{前缀}-{日期}.md`：前缀取自 IOTO Framework Settings 的 `fleetingNotePrefix`（中文默认 `闪念`），「日期」部分由 `fleetingNoteDateFormat` 决定、**格式不固定**（未必是 `YYYY-MM-DD`）。示例里的 `2024-01-01` 只是某个真实闪念文件名，**不要**用 `[[闪念-YYYY-MM-DD]]` 这类写死的占位去回链。

要点：

- `Project` 沿用源闪念或活动笔记的 `Project` 属性。
- 文末 `## 来源` 必须保留，列出**全部**派生该卡片的闪念 wikilink（按真实文件名），不可丢失来源。
- 已存在同主题卡片时，不新建，而是并入该卡片并在 `## 来源` 追加回链。

## 处理清单模板（状态文件）

路径：`0-辅助/IOTO/闪念卡片化状态.md`

由 ioto-llm-output 维护，记录「闪念 → 卡片」映射，作为增量判定的权威依据，也便于审计。源笔记 frontmatter 的 `cardified: true` 仅作可视化兜底，不替代本清单。

```markdown
# 闪念卡片化状态

> 由 ioto-llm-output 维护。记录「闪念 → 卡片」映射，用于增量判定与审计。

## 已处理闪念

| 闪念 | 对应卡片 | 处理时间 |
|------|---------|---------|
| [[闪念-2024-01-01]] | [[IOTO的学思行框架是什么]] | 2026-08-08 |
| [[闪念-2024-01-02]] | [[PEACE工作法是什么]] | 2026-08-08 |
```

每次运行后向表格追加新行；同一闪念若并入多张卡片，分行记录。

## 冷启动回填

若清单为空或缺失，可从现有卡片的 `## 来源` 回链反向推导出「已处理集合」，逐行回填上表，再切回 `incremental` 日常运行。
