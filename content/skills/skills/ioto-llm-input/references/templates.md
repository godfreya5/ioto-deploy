# 笔记模板与拆分原则

## 原始资料笔记模板

路径：`1-输入/原始资料/{描述性标题}.md`

```markdown
---
Project: ["项目名"]
SourceURL: https://example.com/article
SourceType: 网页
---

# {描述性标题}

{清洗后的全文，保留原有标题层级、列表、代码块、表格}

## 碎片笔记

- [[概念A]]
- [[概念B]]
```

frontmatter 字段说明：

- `Project`：数组格式，值来自活动笔记的 Project 属性或用户指定
- `SourceURL`：仅网页/在线来源填写；本地文件可省略或填原文件名
- `SourceType`：网页 / PDF / Word / PPT / 文章，便于日后筛选（可选）

## 碎片笔记模板

路径：`1-输入/碎片笔记/{概念名}.md`

```markdown
---
Project: ["项目名"]
---

# {概念名}

{自包含的概念阐述：是什么、为什么重要、怎么用。
用自己的话重组，不是简单复制原文段落。}

{可选：示例、代码块、对比表}

---
来源：[[原始资料标题]]
```

## 拆分原则（LLM Wiki 风格）

**什么值得拆成碎片笔记：**

- 独立的概念、术语、模型（如「5W2H模型」）
- 可复用的方法、步骤、技巧（如「Dataview中的日期函数」）
- 有明确结论的观点或判断
- 独立的代码片段/函数用法（标题可用 `Code-` 前缀，跟随现有惯例）
- 人物、工具、产品的独立介绍

**什么不值得拆：**

- 过渡性叙述、背景铺垫、作者的个人经历流水账
- 脱离上下文就失去意义的内容
- 与现有碎片笔记重复的概念（改为引用现有笔记）

**质量标准：**

1. 标题即答案：看到标题就知道这条笔记讲什么
2. 自包含：不依赖原文上下文也能读懂
3. 重组而非摘抄：用清晰的结构（定义 → 要点 → 示例）重写
4. 单条笔记聚焦一件事，超过一件事就再拆

**查重方法：**

```bash
# 按文件名查
ls "1-输入/碎片笔记/" | grep -i "关键词"
# 按内容查（obsidian-cli）
obsidian search query="关键词" limit=10
```
